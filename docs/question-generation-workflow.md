# 獨立新題的本機品質流程

本頁是 [#60](https://github.com/CarlLee1983/ExamRemix/issues/60) 的已實作入口；品質判準仍以[新題契約](question-generation-contract.md)為準。AI 在本機產生與求解，網站不呼叫 AI。此入口只接受完整的獨立新題批次；題組的持久品質流程由 #61 承接。

## 1. 固定來源與請求

以一份原卷或可交付卷為批次，選定固定 `batchId`、`new-*.yaml` 目的檔名、原題 ID、數量、完整考試範圍及約束。資料目錄依序取使用者明示值、`EXAMREMIX_DATA_DIR`、repo `data/`，傳給所有命令時明寫相同絕對路徑。

```sh
pnpm bank:batch inspect /absolute/data
pnpm list:questions /absolute/data --eligible --id source-01
```

從索引找來源，逐一核對資格結果，再讀完整原題 YAML。未回傳、未分類、疑點、任一圖形式、題組成員、來源不是原題、多來源的題型／單元／範圍不一致或考點不明均停止，列 ID 與缺少的證據。不能改來源或解除疑點補足數量。

請求沿用[完整批次請求](bank-operations.md#準備與發布完整候選)的欄位，另加 `rules`、`comparisons`，數學另加 `arithmetic`。開始後固定批次、來源版本、數量及約束；原題與比較範圍變動會停止，不能只更新雜湊繼續使用舊核對結果。同批衝突不能靠換 `batchId`、檔名或清掉紀錄重置嘗試。

```json
{
  "rules": {
    "concept": "二位數不進位加法",
    "allowedChanges": "換同位數運算元及生活情境",
    "invariants": "一個加法步驟、兩個二位整數、不進位、單位均為個",
    "verification": "按位相加，再以減法回推，從題意獨立確認單位"
  },
  "comparisons": [
    {"left":"new-one-01","right":"source-01","decision":"distinct","reason":"換運算數字並重新求解，非只調序或換姓名"}
  ]
}
```

這是附加欄位示例，須與既有完整請求合併，不是可單獨執行的請求。`rules` 描述必須具體；無法寫出考點、程度或驗證方法時停止，不以「正確」「同難度」充當證據。

## 2. 在題庫外產生與核對

一次候選仍是完整 YAML，獨立題 `no` 從 1 到指定數量，固定每題位置與來源。候選與請求放在題庫、public 及建置輸出外；`candidateHash` 綁定實際 YAML 位元。依契約產生同考點的新內容，逐題獨立解題、另法核對、判斷唯一性或開放題判準，再寫最終解析。

`evidence` 沿用既有逐題欄位，記錄真正的解法、第二種核對、難度、唯一性、解析及提示檢查。國語核對字音語境與仿作關係；英語核對句義、文法、程度與個人回答的開放性；自然核對條件與因果；社會核對角色與適用情境。內容變動後重新核對所有對應證據，不能複製舊解析或只寫模型自評分數。

比較涵蓋**全部目標題庫（含疑點）、其他待發布批次與本批候選**。`inspect.pending` 提供候選內容、目的檔與 ID；`generations` 提供各批最後狀態與已用次數。為每個本批 ID 填齊與全部外部 ID 的配對；本批兩兩配對只列一次，`left` 使用先出現的題號。每組 `decision` 為 `distinct`、`duplicate` 或 `uncertain`，附具體差異／重複原因。缺配對、重複配對、重複或不確定判斷都拒絕整批。正規化攔截只是補充，不能證明語意不同。

從孩子可見內容核對提示：題幹、選項、注音及本批其他小題是否洩漏答案；材料證據及仿作例句屬必要資訊。錯解析、難度漂移、近重、歧義或提示洩漏，以該題 `decision: "reject"` 和具體原因回報。事實無法確認或工具失敗時加頂層 `haltReason`，直接停止整批；不靠重出掩蓋未知事實。

完成條件：全部候選及每個比較都有可追查的內容判斷，而不是僅有 schema 通過。

## 3. 明確數學模型

數學必填 `rules.mathSources`（每個原題 ID）與 `arithmetic`（每個新題 ID），各項為 `{id, model}`。下列模型代表 12 + 23 = 35；來源模型凍結在約束中，候選填自己的運算元與結果。

```json
{
  "steps": [{
    "operator": "+", "operands": ["12", "23"], "result": "35",
    "ranges": [{"min":"10","max":"29"},{"min":"20","max":"39"}]
  }],
  "inputUnits": ["個", "個"], "outputUnit": "個", "conversions": 0
}
```

數值皆為非負十進位字串。`+`、`-`、`×` 精確支援整數與小數；`÷` 只支援整數商與餘數，另填 `remainder`（未填為 0）。每步兩個運算元，多步按解題順序列出。不同來源的難度特徵必須一致。來源不在支援的明確模型內時停止，不假裝已完成自動驗算。

入口核對精確結果、步驟／運算順序、運算元與結果位數、小數位、零、進退位各欄與跨零、乘法部分積及加總進位、除法整除／商位數／餘數，以及單位／換算次數。可選 `ranges` 表達比位數更窄的上下界，來源與候選使用同一範圍並各自通過。直式模型另外直接綁定結構化運算元與答案；其他題型的文字、算式選擇、題意建模、量級及答案／解析對應仍須獨立求解證據，不任意解析自由文字，也不把模型計算正確當成題意建模正確。

## 4. 提交、有限重出與恢復

```sh
pnpm bank:generate /absolute/work/request.json
```

入口持鎖核對版本與來源，在資料根目錄旁的受管控制目錄保存來源、完整候選、內容／證據指紋與逐題累計次數，再核對品質及完整題庫。首次 `evidence[].attempt` 填 1；同一題的候選、證據、數學模型或相關配對修訂，下一次填前次輸出次數 + 1。其餘完全相同的題目沿用次數。相同請求重跑不加一次；換 `batchId` 的相同指紋也不能重置。

拒絕回傳 `rejected`、各題 `attempts`、原因及 `added: 0`，狀態碼非零；在題庫外重出有問題的題，重驗最終答案、解析、配對及跨題提示後再提交完整批次。任一題第三次仍未通過，或修訂會超過三次，整批成為 `stopped`，不可縮減數量發布。判斷不明／工具錯誤直接停止，保留候選與紀錄。

全部通過後，入口保存不可變候選與發布請求，自動呼叫已驗收的可靠 `bank:batch publish`；沒有直接寫 `bank/`、撞名加後綴或先入庫再修的成功路徑。`published` 才代表整批新增，`added` 不可因重跑再累加。若中斷，使用同一請求重跑；保留候選可恢復，不依賴外部暫存 YAML 仍存在。來源／待發布版本改變、紀錄損毀、外來維護標記或交付檔衝突時停止，保留 ID、雜湊、錯誤與下一個需核對的範圍。

需要撤回已發布成果時使用[指定批次回復](bank-operations.md#回復已發布批次)。回復後同指紋重跑回傳 `reverted`，不是可用新題，也不自動重發。日後內容有疑點仍依既有疑點流程處理。

## 5. 回報與證據界線

回報真實狀態、原批次／新題 ID、逐題來源與答案、所有警告、失敗題的已用次數及缺口。成功後可用 `EXAMREMIX_DATA_DIR=/absolute/data pnpm dev` 的 `/bank/` 預覽；失敗不宣稱新增容量，不改別人的資料。

合成端到端案例見 `tests/generation-cli.test.ts`：五科正反例、字音／仿作、開放答案、難度漂移、整除、單位、近重比較範圍、有限嘗試與恢復。語意拒絕是案例中有具體求解依據的判斷輸入；程式保證保存與執行這些判斷，沒有通用的事實、語法、近重或提示判定器。這些例子不證明所有未來 AI 新題永遠正確。
