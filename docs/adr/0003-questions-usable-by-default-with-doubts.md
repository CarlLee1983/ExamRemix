# 題目預設可用，以疑點取代確認

原本每題原題與新題都要家長逐題確認才能放進試卷，但新題產生時已逐題驗算、原題照印刷抄錄，錯誤率低，逐題核對的成本卻隨題庫線性成長（例如三份自然期中卷 99 題一直未確認而無法組卷）。因此改成題目預設可用、有問題才記**疑點**：疑點只有兩個來源：agent 解析時判斷有問題（匯入時讀不清楚或推定的題目）直接帶疑點進題庫，並在回報中交給家長對照原卷；家長在網站上看到異常則開公開的 GitHub issue（只寫題目 ID 與問題描述），由本機的 agent 處理。網站維持純靜態、唯讀，也不顯示疑點；有疑點的題目不能放進新試卷、不能衍生新題，已組好的試卷若引用到則只在 `check:bank` 與建置時警告，不讓整站建置失敗。代價是沒人看過的題目也會進試卷，錯題要等孩子作答或家長對答案時才被發現。

**Falsified if:** 家長在已列印的試卷中發現錯題的頻率高到想恢復逐題確認，或 agent 匯入時漏標不確定題（試卷上的錯題多半來自匯入時就該標疑點的題目）；此時應恢復題庫 schema（`src/domain/schema.ts`）的確認欄位與跨檔檢查（`src/domain/bank-check.ts`）中「試卷只能引用已確認題目」的規則。
