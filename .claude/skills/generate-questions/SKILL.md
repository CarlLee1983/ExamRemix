# 產生新題

用語以 `GLOSSARY.md` 為準。題型與各欄位的寫法以 `README.md` 為唯一依據，寫 YAML 前先讀它的「題型」以下各節；衍生規則見 `README.md` 的「題庫檢查」。

## 先選生成單位

獨立原題：依[獨立新題品質流程](../../../docs/question-generation-workflow.md)固定來源、保存逐題求解與比較證據，使用 `pnpm bank:generate` 完成有限重出與可靠入庫，最後依該流程回報。這個分支不接續下方寫題庫步驟。

完整題組：以下保留既有題組流程；#61 尚未交付題組的持久嘗試與品質調度。依完整原組處理，不把組員交給只接受獨立題的 `bank:generate`。

## 既有完整題組流程

實際修改資料前，先讀 [題庫受管操作](../../../docs/bank-operations.md#所有受管修改與一致性讀取的共同協定)，將本次寫入放在 `bank:access write` 的前景腳本內，使用準備時的 `targetHash` 並在鎖內核對。完成條件是受管入口成功且完整題庫檢查通過；忙碌或持久維護標記未解除時停止並保留證據。

## 1. 確定原題與數量

把家長的話換成明確的原題 ID 清單與新題數量，數量不清楚時先問。資料目錄依序取：家長指定的目錄、環境變數 `EXAMREMIX_DATA_DIR`、repo 根目錄的 `data/`。

```sh
pnpm list:questions <資料目錄> --eligible --id <原題 ID> [--id <原題 ID> ...]
```

原題若屬於題組，先讀所在題庫的 `groups` 與全部成員：以完整題組為生成單位，數量指新題組數；家長只給部分成員或數量單位不清楚時，先確認完整題組與組數。材料的 `source` 可省略，以成員的原題來源判定；材料有疑點、題組本身有 `derivedFrom`、或任一成員不合格時，回報並停止。原題組內可混合題型與單元，依 `members` 順序逐題繼承，格式與來源規則見 README 的「題組衍生」。

逐一比對請求 ID 與 `--eligible` 結果，任何 ID 未回傳就停止並列出原因；依 README「考試範圍與可用容量」核對所有原題完整範圍一致，新題逐題明寫相同 `examScope`，不能以全都未分類當作一致。

每個原題都必須：存在、沒有疑點（`list:questions` 的疑點欄是 `-`）、本身是原題（有 `source`，不是 `derivedFrom` 的新題）。任何一項不符就停下來告訴家長是哪一題、哪一項，不要換別的題目代替。

原題或題組材料有圖時不能衍生新題：附圖（`image`）、圖片選項、圖片欄標題，以及圖示標示題都算。遇到時告訴家長這題無法衍生，不要換別的題目代替。

完成條件：原題清單全部合格，數量確定。

## 2. 出題

讀原題的完整 YAML，產生新題：

- **繼承**：`type`、`subject`、`grade`、`unit`、`examScope` 與原題完全相同（單元沒寫就都不寫）；原題有 `space` 覆寫且新題長度相近時一併沿用。
- **題組**：每組改寫新材料並產生全部搭配的新題；逐題確認答案能從新材料得出，材料、新題與原組及其他新組不近重。依 README「題組衍生」保存整組與各題的來源對應。
- **變化**：換數字、情境、人名、詞語，保持同樣的考點與難度；新題之間、新題與原題之間不可重複。國語題換用同年級程度的字詞。
- **表格與勾選**：表格填答題保留整張表為一題，核對欄列及答案對應；勾選題核對全部正確選項，至少一個。
- **英語格式**：沿用 [import-original 第 2 步的英語題型規則](../import-original/SKILL.md#2-逐題讀出印刷內容)，只產生可匯入的題型；字母填空、配對與方括號跳脫依同一規則處理。原題或材料有圖時仍依第 1 步停止。
- **欄位**：出處只寫 `derivedFrom`，列出參考的所有原題 ID；驗算過的新題直接可用，不帶疑點。

## 3. 寫答案與解析並驗算

每題寫出答案與給家長看的解析。數學題逐題驗算：用與解題不同的方式再算一次（例如乘法用除法回推、加法用減法回推），兩次不一致就重出這題；直式計算的 `answer` 必須等於運算結果。

社會新題依 [import-original 第 3 步的社會題答案依據](../import-original/SKILL.md#3-寫答案與解析)逐題核對；沒有把握就重出，仍無法確認時停止並回報，不把推定答案列為可用新題。

英語新題依 [import-original 第 3 步的英語題答案依據](../import-original/SKILL.md#3-寫答案與解析)逐題核對題目內容與答案；沒有把握就重出，仍無法確認時停止並回報。

完成條件：每題都有答案與解析，數學題都驗算過且一致，英語題的拼字、大小寫、標點與答案均已核對；題組每題都與新材料相符，成員數及對應順序完整。

## 4. 寫題庫檔

一次產生的新題存成一個題庫檔：`<資料目錄>/bank/new-<第一個原題 ID>-<今天日期 YYYYMMDD>.yaml`，例如 `new-sample-math-26-20261027.yaml`；撞名時在後面加 `-2`、`-3`。`no` 從 1 起連續編號，題目 ID 會成為「題庫檔名-兩位數序號」。

## 5. 檢查到通過

```sh
pnpm check:bank <資料目錄>
```

有錯誤就修這次寫的題庫檔後重跑；錯誤出在其他檔案時，停下來告訴家長，只改這次寫的檔案。

完成條件：摘要是 0 個錯誤（狀態碼 0），或其他檔案的錯誤已回報給家長。

## 6. 回報

告訴家長：題庫檔路徑、新題 ID 與各自衍生自哪些原題、每題的答案；題組另列新題組 ID、原題組 ID 與材料核對結果；`check:bank` 的每一則警告，以及預覽方式 `EXAMREMIX_DATA_DIR=<資料目錄> pnpm dev` 後開 `/bank/`。家長在網站上看到哪題有錯，開 GitHub issue（只寫題目 ID 與問題描述），由 agent 在本機用 record-doubt skill 處理。
