# 記錄或解除疑點

疑點的意義見 `GLOSSARY.md`「疑點」與 ADR 0003；agent 只動家長點名的題目。

資料目錄依序取：家長指定的目錄、環境變數 `EXAMREMIX_DATA_DIR`、repo 根目錄的 `data/`。

## 1. 確定題目與情境

把家長的話換成明確的題目 ID（「題庫檔名-兩位數序號」，`no` 就是序號），用 `pnpm list:questions <資料目錄> --id <ID>` 對照；ID 不存在就回報給家長，不要猜。再判斷是三種情境中的哪一種：

- **記錄**：家長給了 ID 與疑點描述（「記錄 sample-math-22 的疑點：答案應為 2」）。
- **修正後解除**：家長要你修好這題（「sample-math-22 的疑點修好它」）。
- **判定沒有疑點後解除**：家長說這題的疑點沒問題（「sample-math-22 的疑點沒問題」）。

家長交來 GitHub issue 時，用 `gh issue view <編號>` 讀出題目 ID 與問題描述，自己對照題目判斷，不必問家長：確認有錯就當成**修正後解除**直接修好；確認沒錯就不改題目；判斷不了才當成**記錄**寫進疑點。處理完在 issue 留言並關閉：repo 是公開的，留言只寫題目 ID、處理方式與判定依據的類別（例如「答案與原卷印刷一致」「已修正答案」），不引述題幹、答案或其他私人題目內容。

完成條件：每個 ID 都存在，且各自對應到一種情境；說不清是哪一種時先問家長（GitHub issue 例外：判斷不了一律當成**記錄**）。

## 2. 找出衍生題

```sh
grep -rn "<ID>" <資料目錄>/bank/
```

列出 `derivedFrom` 引用這題的新題。**記錄**的情境下，有衍生題時先告訴家長：記下疑點後，這些新題會讓 `check:bank` 回報錯誤、網站無法建置；請家長選擇刪掉這些新題（連同引用它們的試卷題目），或先不記錄。家長選定前，題庫檔保持原樣。

完成條件：衍生題清單已列出；記錄情境下有衍生題時，家長已做出選擇。

## 3. 改題庫檔

只改對應題目，以及家長在第 2 步選定刪掉的新題與試卷題目。

- **記錄**：寫入 `doubt`，內容是家長描述的一句話，寫成看得懂要核對什麼（例如「答案疑為 2，原卷第三個選項模糊」）。這題已有 `doubt` 時，把兩件事併成同一句。
- **修正後解除**：依 `doubt` 與家長的話修正題幹、選項、答案或解析，寫法以 `README.md` 的「題型」以下各節為準；數學題用與解題不同的方式再算一次，兩次一致才算修好。修好後刪掉 `doubt`。缺的資訊（例如原卷看不清的字）家長沒給時，停下來問，`doubt` 保留。
- **判定沒有疑點後解除**：只刪掉 `doubt`，題目內容保持原樣。

## 4. 檢查

```sh
pnpm check:bank <資料目錄>
```

有錯誤就修這次改的檔案後重跑；錯誤出在其他檔案時，停下來告訴家長，只改這次點名的檔案。

完成條件：摘要是 0 個錯誤（狀態碼 0），或其他檔案的錯誤已回報給家長。

## 5. 回報

告訴家長：每個 ID 做了哪一種處理、修正了哪些欄位、刪掉了哪些新題，以及 `check:bank` 的每一則警告（例如試卷引用了剛記錄疑點的題目）。修正的是原題且有衍生題時，一併列出，讓家長決定要不要重新產生。
