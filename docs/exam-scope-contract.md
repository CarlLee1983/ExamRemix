# 考試範圍與可用容量契約

對應 [#47](https://github.com/CarlLee1983/ExamRemix/issues/47)，決策見 [ADR 0006](adr/0006-exam-scope-and-paper-eligibility.md)，用語見 [GLOSSARY](../GLOSSARY.md)。本票交付資料邊界、遷移／回復原則及後續實作驗收，不修改正式 YAML、不實作遷移器或抽題器、不新增正式題目。

#48 後續已選定的五科題量、配分與抽題規則集中於[完整卷配置與抽題契約](paper-composition-contract.md)；本文件的可用容量不等於符合該配置的完整卷能力。兩份契約的程式補強均尚未實作。

使用者已確認：每題只屬於一個考試範圍；首版只啟用三年級上學期期中五科；不保留不合格舊試卷的公開網址及列印。題目預設可用、有效疑點與題組材料規則仍沿用 [ADR 0003](adr/0003-questions-usable-by-default-with-doubts.md)／[ADR 0004](adr/0004-question-groups-share-material.md)，但既有試卷只警告仍輸出的規則由 ADR 0006 取代。

## 範圍屬於題目，單元與來源保持原義

完整範圍為 `(grade, semester, stage, subject)`。保留既有 `grade`（1–6）與 `subject`（國語、英語、數學、社會、自然），在題目及試卷增加可選的完整物件 `examScope`：

```yaml
grade: 3
subject: 數學
examScope:
  semester: 1
  stage: midterm
```

`semester` 僅接受整數 `1`／`2`，`stage` 僅接受 `midterm`／`final`；分別顯示上／下學期、期中／期末。物件存在就必須兩欄完整且不接受額外鍵，不能只填學期、填空值或以 `unknown`／`第一次評量` 冒充階段。完全省略表示範圍尚未知，不是預設三上期中。`grade`、`subject` 不在物件內重複保存。

既有資料允許暫時省略 `examScope` 以便逐批遷移；新匯入、產題及組卷入口必須在發布前取得完整範圍，不能藉省略欄位通過可用性檢查。這是分類資料，不增加 `confirmed`、審核通過等逐題確認狀態。原題內容沒有疑點就維持預設可用，但必須先有分類證據才會出現在某範圍的可用容量中。

每個題目 ID 只對應一組範圍；不以陣列保存多個範圍，不把同一題複製成另一個 ID 供跨範圍使用。期末可能涵蓋期中知識，但首版不因此自動借用期中題；此分類不宣稱同年級各校或各版本教材的考試內容完全相同。`unit` 仍是選填學習分類，不能拿來推導學期／階段。`source` 保留原卷位置，`derivedFrom` 保留來源鏈，不改寫為範圍欄位。

不在題庫檔頂層、目錄名稱或題組再保存一份範圍預設值。題庫檔可以保存不同範圍的獨立題，不能將檔名改成 `midterm` 就使全部題目取得分類。這比檔案級分類多出逐題欄位，但不需要搬動檔案、重編 ID 或讓讀取端猜測覆寫順序。

## 分類證據與繼承

核對原卷印刷年級、學期及考試階段，必要時以可對照的來源紀錄補證。來源只寫「第一次評量」時，沒有額外證據不能視為期中。檔名、目前所在 `data/`、封存目錄、既有 `unit`、原型下拉選單都不是充分證據。

以一份原卷或一張可交付試卷為批次，於不公開的操作紀錄保存原題 ID、來源檔／頁次或紀錄位置、來源雜湊、判定範圍與理由；同卷可共用一筆證據並明列涵蓋 ID，不要求家長逐題審核。不把私有原卷路徑及掃描檔新增到網站產物。找不到證據則保持未分類並列出原因；內容有疑點才使用既有 `doubt`，不能以解除疑點代替分類，也不能為了湊容量臆測範圍。

| 實體／操作 | 必須成立的規則 |
| --- | --- |
| 原題 | `grade`、`subject` 與分類證據一致，`examScope` 只有一份；同一實體原卷的證據不能對成員給出相衝突分類 |
| 多來源新題 | 所有原題完整範圍完全一致且可衍生；新題明寫相同 `examScope`，連同既有 `type`、`grade`、`subject`、`unit` 一起驗證。任一來源未分類、跨範圍或有有效疑點即拒絕 |
| 原題組 | 不另寫 `examScope`；所有成員完整範圍一致才可推導題組範圍。任一成員未分類則整組範圍未知，成員範圍衝突是資料錯誤，不能由所選子集推導另一個範圍 |
| 新題組 | 保留整組、成員位置與來源對應，每個新成員繼承對應原題；材料與任一原組員有疑點時不能衍生，與 #46 相同 |
| 試卷 | 明寫 `examScope`，每個引用題目與試卷的完整範圍一致；題組只選部分成員仍須檢查完整原組的範圍，並保留材料在前、同大題連續排列 |
| 修正分類 | 必須列出受影響新題、題組與試卷，不能只改原題而放任來源鏈不一致；不得自動替換試卷題目來消除衝突 |

題組「範圍未知／衝突」與「疑點」不同：前者使整組都無法歸類；後者沿用 `effectiveDoubt`，材料疑點排除整組，單一成員的內容疑點只排除該成員，其他已分類成員仍可供試卷節選。但衍生新組仍要求所有原組員無疑點。

這擴充 [#46 契約](question-generation-contract.md) 的輸入與繼承檢查：產題請求指紋納入完整範圍及其來源版本；來源分類改變使舊驗證失效。#46 的單一新檔發布器不等於既有資料的跨檔遷移器。

## 支援範圍、可用容量與完整卷

一份共用的支援範圍清單由程式的範圍模組持有，供建置與前端使用，不讓 UI 及檢查器各存一份。首版固定五個組合：`grade: 3`、`semester: 1`、`stage: midterm`，各配一個現有科目。資料字典能表示其他年級／學期／階段，不表示產品已啟用它；日後擴大支援須另做資料核對、配額及入口驗收，不以掃到一份封存 YAML 自動啟用。

對範圍 S 的可用容量，計算同一份已驗證資料快照中符合以下條件的不同題目 ID 數：完整範圍恰為 S、格式及來源關係有效、所屬題組也已完整歸類、沒有有效疑點、題型與必要附圖可被現有程式支援、已完整入庫且未回復。原題與合格新題都可計入；重複引用同一 ID 只計一次。獨立圖片題只要格式與圖片有效就可以挑選，不能誤把 #46「不可由圖題衍生」當成「圖題不可組卷」。

材料本身不另計一題；配對、分類、整張表格或圖示標示題各依其題目 ID 計一題，不能按空格或配對數灌水。題組成員各按題目 ID 計數，另報完整可用組數時需所有成員均可用，兩者不相加。某成員有疑點時，其餘可用成員仍可計入可選題數，但該組不算完整可用組。

範圍未知、有效疑點、題庫外候選、失敗或回復批次、未載入封存及不支援題型一律不計。待核對分類也不計；不因題目有既有試卷引用就特准可用。同源新題可各計為可選題目，但這不代表能放在同一卷或是互不近重的容量。跨 ID 近重、同源排除、題型配額及重抽差異由 #48 決定；不能用可選題數除以預設卷題數宣稱可出 N 份互不重複完整卷。

| 入口狀態 | 判定與可觀察行為 |
| --- | --- |
| 未支援 | S 不在支援清單；顯示未支援，不嘗試從別的範圍借題，封存有資料也不自動開放 |
| 沒有題目 | S 已啟用、資料快照成功驗證且可用容量為 0；顯示沒有可用題目，不把未知分類數算進去 |
| 完整卷規則尚未配置 | S 已啟用且容量大於 0，但 #48 的該科配額／抽題規則未就緒；可報可選題數，不宣稱足夠或不足，不啟用隨機組卷 |
| 不足一份完整試卷 | 規則已就緒，但依 #48 規則無法形成完整一卷；明列缺少題型／限制與缺額，不減題、不補疑點題、不跨範圍借題 |
| 可組完整試卷 | 用同一快照及規則實際驗證可行，才啟用組卷；#48 負責配置與可行性邊界，不在本票指定各科題數 |
| 資料載入／驗證失敗 | 顯示載入失敗，不偽裝成容量 0 或不足；保留上次版本時須明示其版本，不混用新舊統計 |

現成試卷與隨機組卷分別驗證：前者只列出範圍、題目可用性、完整卷配置及列印條件均合格的試卷，不能因資料夾裡有一份 YAML 就當作完整卷。未取得 #48 的完整卷配置前，不把歷史練習卷標為預設完整試卷。列印就緒與互動方式由 #49 承接。

後續實作在共用範圍模組集中完整範圍比較、支援清單、題目／試卷資格與容量計算；`check:bank`、`list:questions`、建置載入器、首頁統計及組卷入口共用其結果。`list:questions` 增加學期及階段篩選（`--semester 1`、`--stage midterm`），與既有年級／科目條件一起匹配；`--no-doubt` 本身不等於範圍已知或可組卷。匯入／產題／組卷 skill 必須改用完整範圍檢查，不各自實作預設分類。這些工具與欄位目前均尚未補強。

## 舊試卷停用與發布

使用者選擇不保留不合格舊卷的公開網址及列印。任一引用題目範圍未知／不一致、有效疑點，或試卷自身未分類時，整份試卷停用：不產生試卷頁及答案卷、不出現在列表／搜尋／現成卷入口，也不留下題庫「用於」的可點連結。原網址回傳未找到（404），不能仍回傳含題目或答案的 HTML、可列印隱藏頁，或靜默導向另一卷。對非支援範圍的試卷同樣不提供首版公開試卷頁。

本機保留原試卷 YAML、原始引用與 ID，檢查工具列出試卷 ID、各題 ID 及停用原因。範圍完整但帶疑點的題目保留分類，在包含該疑點的資料快照中即排除容量及試卷資格，不沿用舊資格結果；解除疑點或補齊有證據的分類後，仍須重新驗證整卷才恢復輸出。靜態網站要重新建置及部署才會反映變更，修改本機 YAML 不會即時撤下已部署頁面。

錯誤分層必須明確：YAML／schema 格式錯、缺圖、引用不存在、來源鏈或題組成員範圍互相衝突是資料錯誤，阻擋建置；合法但尚未分類、試卷與題目範圍不同、疑點或未啟用範圍則回報排除原因並停止輸出該卷，不必讓其餘合格試卷一起消失。新產題／新組卷入口遇到任何此類不合格條件都拒絕發布，不能以「只警告」視為本批成功。排除與路由輸出使用同一個資格判定結果。

建置需使用乾淨的輸出目錄，不能沿用上次殘留的試卷頁；部署要整版替換或確實刪除已停用路徑、處理既有快取，再檢查原網址不提供舊內容。具體主機／快取操作交給 #50，不以本文件宣稱線上刪除已完成。已下載或印出的副本無法追溯收回。

## 遷移與回復邊界

本票不遷移資料。後續應按原卷／可交付試卷批次執行下列流程，不新增或重新生成題目，不全量改名，不因分類把題目搬到另一份檔案而改變 ID：

1. 固定程式版本、資料根目錄及來源版本，盤點題庫、圖片、題組、試卷引用與封存。在題庫掃描及網站輸出範圍外建立隔離工作副本及可恢復備份，記錄檔案雜湊、存在／不存在狀態、舊分類、新分類、證據、受影響 ID 及所有預期修改。正式資料按批次保留必要證據；故障測試用小型 fixture，不為每個案例複製整份正式題庫。
2. 只對有證據的原題補 `examScope`，由原題檢查並傳遞給所有新題，再驗證完整題組與試卷；無法判定的保持未分類。來源不一致、同名目的已有不同內容或多來源分類相衝突時停下，不自行選一個分類、不覆寫。
3. 核對遷移前後 `questions[].no`、題目／題組 ID、`source`、`derivedFrom`、材料、答案、解析、圖片路徑與位元內容、試卷引用及排序完全不變。唯一資料變化是有證據的分類欄位；試卷不能因不合格而刪除引用或改題。用合格／排除原因清單與可用容量差異說明預期發布影響，不以原始總題數當作新容量。
4. 在隔離資料視圖驗證完整快照及新輸出，確認不合格舊路由已移除；驗證失敗就不切換正式資料／產物。正式套用採維護窗口與持久化遷移紀錄，不引入資料目錄符號連結：取得排他鎖，重新核對輸入雜湊，先持久化變更清單／備份／遷移中標記，再套用本批分類變動、同步檔案及目錄並驗證整體。所有讀取、匯入、產題、組卷、建置及容量查詢都必須共用鎖並檢查標記；遷移中拒絕讀取正式資料，不讓讀者看到逐檔更新的中間版本。完成驗證並持久化完成狀態後才解除阻擋。這是受控維護操作，不能稱逐檔寫入本身為原子交易；現有已部署靜態版本可持續提供服務。
5. 同批重跑核對批次識別、輸入及最終雜湊；內容已符合且完整時是無操作，不重複添加欄位、不新建 ID。中斷後先判定仍是舊快照或完整新快照；持久標記不能隨程序退出或鎖釋放而消失。發現未完成或混合版本時繼續拒絕讀取及發布，恢復者取得排他鎖後，依紀錄完成本批或回復到完整舊狀態，驗證成功才解除標記。成功後保留可回復紀錄，不清理唯一來源證據。

回復須同樣以批次及排他協定進行，先檢查本批修改後的檔案雜湊及依賴是否仍符合紀錄。只還原本批擁有的分類變動／資料快照，保留其他批次及使用者修改；發現後續修改或依賴衝突時停止並列出，不用整份舊備份直接蓋回工作區。回復必須恢復資料與相容的程式／產物版本並重驗；只回復 metadata 不會自動回復已部署網站。

原始 ID、來源、圖片及試卷引用得以保留，表示可以重驗及重新輸出；不表示沿用公開舊網址的可用性。封存資料不整批搬回正式根目錄：期末資料仍屬未啟用範圍，「第一次評量」未確認者仍排除；未支援題型與其附圖繼續保存，日後有支援及證據才按原相對路徑處理。

## 實作驗收與證據界線

以下是待實作的驗收案例，不是本票已通過的程式測試。以小型合成 fixture 驗證公開分類／容量／資格判定與靜態輸出邊界；故障測試使用隔離暫存目錄。

| 案例 | 必須觀察到的證據 |
| --- | --- |
| 完整或未知範圍 | 合法完整物件解析成功；完全缺省為未知且不計容量；半份、錯型、非法 enum、額外鍵被拒絕 |
| 來源僅標第一次評量、檔名含 midterm | 沒有額外證據時仍未知，不能自動填為期中；紀錄排除理由 |
| 同範圍／跨範圍多來源新題 | 前者嚴格繼承；後者或任一來源未知時拒絕；分類修正使舊產題驗證失效 |
| 題組未知成員／衝突範圍 | 未知使整組無法計入某範圍；衝突列資料錯誤，不能靠節選其他成員繞過 |
| 材料疑點／單一成員疑點 | 材料疑點排除全部；單題疑點僅排除該成員，其餘可選數正確，完整組數歸零；整組衍生仍拒絕 |
| 同一 ID 重複引用、表格／配對／圖題 | ID 只計一次；不按空格膨脹題數；有效圖題可挑選但不可衍生 |
| 候選、回復批次、封存及無法載入資料 | 前三者不灌入容量；載入失敗不得顯示為沒有題目 |
