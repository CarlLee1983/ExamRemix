# 本機 AI 新題與入庫契約

對應 [#46](https://github.com/CarlLee1983/ExamRemix/issues/46)，決策見 [ADR 0005](adr/0005-validate-generation-before-bank-insertion.md)。本文件交付決策與後續實作的驗收邊界，不會產生正式新題，也不宣告交易寫入器已完成。AI 在本機 agent 執行；網站維持靜態唯讀，不增加線上 AI 服務或金鑰。

用語及疑點規則沿用 [GLOSSARY](../GLOSSARY.md)、[ADR 0003](adr/0003-questions-usable-by-default-with-doubts.md) 與 [ADR 0004](adr/0004-question-groups-share-material.md)；YAML 欄位仍以 [README](../README.md#題型) 為準。候選題是操作中的暫存內容，不是題庫中新增的題目狀態，不新增 schema 欄位或家長逐題確認流程。

## 輸入及停止邊界

一次請求固定以下內容並記錄在題庫外的操作紀錄，開始後不得默默替換：

- 正規化後的絕對資料目錄：明示目錄、`EXAMREMIX_DATA_DIR`、repo `data/` 依序選取；檢查指令必須明帶同一目錄，避免 `check:bank` 預設讀 `examples/`。
- 批次範圍以一份原卷或一張可交付試卷為單位，記明對應原卷／目標試卷及本次選題範圍；不能把互不相關的擴充混成一批。
- 原題 ID 清單與完整 YAML；題組須包含原材料、依 `members` 排列的所有成員。保存來源檔及相關資料快照的內容雜湊。
- 數量及單位：獨立題以題計；題組以完整新組計，另報小題總數。只給組員 ID 時擴展成完整原組並明列，不足以判定意圖或數量時先釐清。一次操作可有多組，但不能只交付其中部分。
- 每個對應原題的考點與難度約束、允許變動、不得變動、題型規則、驗證方法及最大嘗試次數。預設每題／整組最多 3 次（初次加 2 次重出）；紀錄已用次數，程序重啟不能歸零。
- 批次識別 `batchId`、請求指紋、契約版本及候選結果雜湊。指紋含資料目錄、批次範圍、排序去重後的原題 ID、來源版本、數量／單位及品質約束；同批恢復必須完全相符。相同指紋已有仍在題庫中的完成批次時先核對檔案完整性、回傳既有結果；已回復批次回傳已回復狀態，不能當成可用新題。使用者明確要求再出一批才給新識別，且仍須跨批去重。

原題必須存在、有 `source`、不是新題、沒有疑點。非題組多來源的 `type`、`subject`、`grade`、`unit` 完全一致（包含都未填單元）；題組逐一按位置繼承這四個欄位。新題只記 `derivedFrom`，不冒用 `source`；新材料只指向一個原題組，每個新組員只指向對應原組員，小題數及題型順序不變。

任何原材料或原題含圖片就停止：含 `image`、圖片選項、配對欄內圖片、表格圖片欄標題、圖示標示題。此範圍不產生新圖片，也不能移除原圖繼續出題。來源有疑點、缺少完整組員、混用不合格原題時，列出 ID 與原因停止，不換來源、不自行解除疑點。來源考點或難度無法確定時同樣停止，不靠猜測建立約束。

## 內容品質契約

### 可變內容與不變條件

所有題型維持原考點、同年級程度、解題步驟及必要資訊量；可換數字、情境、人名或詞語，不能只換順序或姓名充數。`space` 僅在內容長度相近且足夠作答時沿用。題組可重寫材料與題目，但必須整組重新求解；不得依賴舊材料、缺少材料或未選入的其他小題。

| 題型 | 可變內容及核對 |
| --- | --- |
| `choice` | 重寫題幹與選項；逐項判斷，恰一個成立，干擾選項合理且不等價，答案編號隨選項同步 |
| `multi-select` | 重寫敘述與選項；窮舉每個選項真假，正確集合完整且非空，不漏選或誤選 |
| `true-false` | 改寫敘述或條件；核對適用範圍及例外，避免雙重否定或缺少條件造成兩解 |
| `fill-blank` | 改寫句子及空格；空格與答案按位置一一對應，封閉題須有可判定答案，不能因改寫而容許未定義的多解 |
| `matching` | 重寫兩欄內容；保留一對一形式，逐端點核對所有可能配對，整體只有一個完整配對解，不能僅重排原項目 |
| `table-fill` | 改寫文字欄列與資料；整表為一題，保留考點與欄列關係，每格依欄列重新求解，避免同義欄位造成歧義 |
| `char-to-zhuyin`、`zhuyin-to-char` | 換同年級字詞及句境；核對字音、多音字語境、注音標記與隱藏字，答案由標記表示，不能硬加 `answer` |
| `make-sentence`、`imitate-sentence` | 換詞語／例句；維持目標句型與程度，範例答案須合語法及題意，解析說明判準，承認其他合格答案 |
| `personal-response` | 改寫同程度的個人問句，保留 `writingGuide: four-line`；`sampleAnswer` 與解析只作示例，不把個人事實判為唯一答案 |
| `horizontal-calc`、`vertical-calc`、`word-problem` | 依下方數學約束換數字或情境；算式、運算元、答句、單位與解析全部重新計算 |
| `diagram-label` 或其他含圖題 | 本契約不支援衍生，停在輸入檢查 |

國語／英語需核對字詞程度、語法、句義及材料對應；自然需核對事實、實驗條件與因果；社會需核對情境、角色關係及規則適用範圍。不能藉改寫改變常識真假或加入超出原考點的外部知識。無法可靠判定時停止，交代需要哪項事實或家長判斷。

### 數學難度與獨立驗算

先從原題解法列出難度特徵；多來源特徵互相衝突時停止並釐清，不能取平均。候選題至少保持：

- 運算種類、順序、步驟數、數值位數與範圍、整數／小數及小數位數、正負與零的限制。
- 進位／退位是否發生、次數及所在位階，是否跨零連續退位；如不進位的題不能因換數字變成進位題。
- 除法是否整除、商的位數、餘數條件；不可引入除以零、未教的分數或循環小數。現有直式 schema 不支援除法，不擴充運算子。
- 單位、換算方向與換算次數、量級及情境合理性；不可把只算數量變成單位換算，也不能讓人數或件數變成不合理小數。

每題先獨立解題，再用另一方式核對：例如加法以減法回推、乘法以除法回推，除法驗證「除數 × 商 ＋ 餘數 ＝ 被除數」及餘數範圍；應用題另從題意確認模型與單位，不能只驗算已抄錯的算式。保存解法、核對方法與結果。精確小數不能依浮點近似宣稱相等。

`vertical-calc` 已有精確結果檢查；橫式、應用題、選擇題中的數學與解析沒有通用求解器。格式正確、兩次重述同一解答或模型自評「正確」都不足以證明答案正確。

### 答案、解析、近重與提示

封閉題必須從題幹及材料推出唯一答案（勾選題為唯一集合、配對為唯一整體映射）；逐一檢查其他答案為何不成立。開放題使用範例及明確判準，不要求唯一句子。每次重出後重新寫答案與解析，解析的數字、人名、條件、選項編號及材料引述必須吻合最終內容，不能沿用舊答案或舊驗證紀錄。

比較範圍包含整個目標題庫的原題與新題（含疑點題）、本批所有候選及其他待發布批次。完整相同或只有姓名、標點、選項／配對順序不同而作答內容相同者拒收；刻意保留考點而換運算數字、重新求解的新題可以成立，不能只因解題模板相同判重。短文改了姓名但問題、線索及答案實質相同仍屬近重。題組同時比較材料、各小題與整組，不能以新材料掩蓋重複小題。

可執行的正規化比對只篩出完全相同及候選近重，不以單一相似度閾值證明語意不同。保存疑似配對 ID、差異與接受／拒絕理由；無法確定是否近重就重出，仍不確定即停止。

從孩子看見的試卷內容核對提示洩漏：題幹直接抄出答案、選項長度／語法／標點獨特性指向正解、注音殘留被考字、其他小題直接提供答案，以及材料不小心標出正解。閱讀材料含解題證據、仿作例句及題型明定的提示是必要資訊，不是洩漏；判斷是否仍需原考點所要求的思考。網站答案卷本來會顯示答案，不把它當成保密問題。

### 重出與停止

可修正的候選內容錯誤（答案不合、難度漂移、歧義、近重、提示洩漏）記錄原因後重出該獨立題；題組任何部分有錯就重出整組並重驗全部。最多 3 次仍未通過便停止整批，不交付縮水結果。來源不合格、事實無法判定、資料衝突、I/O／驗證工具失敗直接停止，不用重出掩蓋。失敗候選及錯誤證據留在題庫外，不能靠附 `doubt` 把未完成新題塞進題庫。已完成入庫的題目日後發現疑點，仍依 ADR 0003 記疑點並排除使用。

## 可靠入庫及回復

### 選擇與所有權

採取「題庫外候選 → 完整驗證 → 單一新檔一次發布」。不選逐題附加後修復（會暴露半批），也不選在 schema 加待確認旗標（迫使所有讀取端認識操作狀態，且背離 ADR 0003）。本契約一次只新增一個無圖片的題庫 YAML；不修改原題、試卷或其他批次。

操作紀錄與候選放在明確工作目錄、目標 `bank/`／`papers/` 及其掃描範圍之外，不隨網站輸出。記錄目標路徑、批次識別／指紋、輸入及候選雜湊、穩定的題目／題組 ID、驗證結果與警告、重出次數及狀態（準備、已驗證、已發布、已回復或失敗）。恢復時以紀錄及實際檔案核對，不能只相信狀態字串。

每個資料目錄只允許一個寫入者進入發布／回復區段，以排他鎖強制執行；其他產題、匯入、組卷及修改疑點的工具都須遵守。準備期間可並行，但各批有獨立工作目錄。建置、容量查詢若要求一致快照，須共用讀鎖或讀取固定快照；未遵守協定的編輯或建置不在保證內，操作時須先停下。不能只靠「agent 應該不會同時寫」。

### 發布順序與重跑

1. 在題庫外生成完整候選，凍結內容及 ID。新檔名可保留 `new-<原題 ID>-<日期>` 慣例，但第一次分配後持久記錄；同批重跑不得改用 `-2`。新批撞名可另取名，ID 隨最終檔名確定後重新驗證。
2. 對來源快照與候選做 schema、跨檔、品質及去重檢查；驗證視圖包含完整目標題庫、試卷與本批候選。使用暫存 overlay／小型 fixture 測故障，不為每個案例複製正式題庫。保存逐題／整組求解證據及全部警告，任何錯誤使整批失敗；與本批無關的既有錯誤也要回報並停止，不修改其他檔案。
3. 取得資料目錄排他鎖，重新比對來源與目標題庫／試卷快照。若有變動，原驗證失效，基於最新快照重跑受影響檢查、品質及去重；不能只更新雜湊後放行。發布前確認原題仍無疑點、ID／檔名仍未占用、所有候選均通過。
4. 先持久化足以恢復的發布意圖、完整候選及雜湊，再於同檔案系統建立、寫完並同步暫存檔；使用原子且「目的存在就失敗」的發布原語，一次讓完整 YAML 出現在 `bank/`。一般會覆寫目的的 `rename` 不足以滿足此條；跨檔案系統複製也不算原子發布。需同步檔案及父目錄，並把暫存檔排除於載入器掃描範圍。
5. 在鎖內核對最終檔案雜湊及完整目標資料的 `check:bank`，持久化已發布結果後才回報新增容量與釋放鎖。題目預設可用，因此可見檔案必須早已整批驗證完成；不讓讀取端依賴操作紀錄過濾半成品。

若發布成功但尚未寫完結果紀錄就當機，恢復時取得同一把鎖：目的檔案與紀錄的候選雜湊、ID 完全相符則辨認為同批，重驗完整性後補記成功、回傳同一結果，不再新增；目的不存在就從已驗證候選繼續，但先驗來源／目標版本；內容不符或紀錄損毀則停止衝突處理，不覆寫、不改名繞過。若來源版本或契約變動，不可沿用舊品質通過結果。

### 回復與容量

發布前失敗只留下題庫外紀錄，正式容量增加 0。發布後檢查失敗時在鎖內依下列回復規則移除本批完整檔案，保留候選、來源雜湊、錯誤及回復結果；不能以成功回報掩蓋失敗。

回復只作用於紀錄所擁有且內容雜湊仍一致的新檔，先檢查其他試卷及題庫是否已引用本批題目／題組。若已被他人修改或引用就停止並列出衝突，由使用者決定後續處置；不刪別人的試卷、不覆寫原題，不恢復整份舊題庫。無衝突時原子移出掃描範圍、同步目錄、記錄已回復，再檢查目標題庫。重複回復已不存在的自有檔案是成功的無操作；不因同名檔存在而誤刪。

只有完整通過且已發布、沒有有效疑點的題目可計入可用容量；題組材料有疑點時整組排除。準備、失敗、未發布、已回復或只完成部分求解的候選一律為 0。發布後當機留下的完整已驗證檔案可被既有載入器讀取；恢復補記不能再加算一次容量。題組同時報完整組數與小題數，不能把兩種數字混加。

## 現況、補強與判斷責任

以下依 #46 開始時的整合工作目錄核對；未提交整合內容不等於 `HEAD` 已提供所有能力。

| 邊界 | 已有 | 後續須補強的可執行檢查 | 仍由本機 AI／人判斷 |
| --- | --- | --- | --- |
| 輸入與來源 | generate-questions 步驟 1–2 要求原題無疑點、無圖、繼承欄位及整組衍生；`bank-check.ts` 檢查來源／欄位／題組對應 | 統一所有圖題的拒絕檢查；目前單題跨檔圖題限制只特別攔截含圖配對，不能視為已涵蓋所有圖題 | 考點與難度特徵是否可確定 |
| 格式與答案結構 | `schema.ts` 檢查選項範圍、配對一對一、空格數、欄列對應與直式精確結果 | 依明確數學約束驗證進退位、整除與單位等可計算條件；不任意解析所有自由文字 | 題意建模、語意唯一性、開放題判準及解析一致性 |
| 品質 | skill 要求同考點難度、數學兩種方法驗算、不可重複 | 保存逐題證據、有限重出、內容雜湊綁定、正規化重複及候選近重清單 | 各科事實／語法、實質近重、提示洩漏；相似度或格式通過不能代替此判斷 |
| 寫入 | skill 步驟 4–5 直接寫新 YAML、撞名加後綴，再跑檢查；現有載入器直接讀題庫 | 批次紀錄、鎖、完整驗證視圖、不可覆寫原子發布、恢復／回復及一致性讀取協定全部待實作 | 衝突或已被引用後的處置決定 |
| 疑點 | ADR 0003／0004 與 `question-groups.ts` 已定義有效疑點排除 | 發布前重新驗證來源、容量不得包含題庫外候選 | 後來發現異常時依既有流程記錄／解除疑點 |

不把更新 skill 的文字當作交易保證；後續實作應先完成發布及故障測試，再讓 generate-questions 改用該入口，移除直接寫入路徑。無新增套件、網站 API 或 schema migration；回退實作時停止新批發布，保留已發布的普通 YAML 與操作紀錄供恢復。

## 實作驗收與既有證據限制

以下是後續實作必須通過的驗收，非本文件已執行的測試。使用小型合成資料與隔離目錄；不擴充正式題庫。斷言最終檔案、ID、雜湊、可見容量、原題不變及重跑結果，不能只看程序退出碼。

| 案例 | 必須觀察到的證據 |
